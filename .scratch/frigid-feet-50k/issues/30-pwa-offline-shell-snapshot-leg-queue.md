# 30: PWA offline shell, IndexedDB snapshot & offline Leg mutation queue

**What to build:** Make Race-Day Leg check-ins bulletproof in spotty outdoor winter cell service by caching the PWA shell and last synced Event snapshot locally, queueing individual Leg taps in IndexedDB with optimistic UI and local/compensating Undo, reconciling conflicts calmly against `apply_leg_mutation`, and clearly disabling online-only structural actions while disconnected.

**Blocked by:** 22: Chip-In progress card & private Organizer ledger; 23: Organizer Supply wish-list, Team overrides & Event Snapshot export; 25: Organizer mass-start (Start Round N) & Race-Day Leg overrides; 26: Live auto-calculated Badges & Organizer superlatives; 28: Single-channel Realtime sync & mobile background resync

**Status:** ready-for-agent

- [ ] `vite-plugin-pwa` (Workbox) precaches the static app shell (`CacheFirst`) and configures best-effort runtime `CacheFirst` caching with expiration for previously viewed Leaflet/OpenStreetMap Course tiles; Service Worker updates never force-reload while `leg_mutation_queue` is non-empty and instead present a gentle *"Update available — Reload"* prompt when idle.
- [ ] IndexedDB `event_snapshot` store (`idb`, keyed by `event_id` with `{ event_id, data, last_synced_at }`) persists after every full Event fetch and merged Realtime change; on offline cold launch, the app hydrates immediately from `event_snapshot`, overlays pending `leg_mutation_queue` items optimistically, and shows a non-blocking top banner: *"Offline — showing last saved view (updated Xm ago)"*.
- [ ] Individual **Leg** mutations (`start`, `finish`, `mark_completed`, `edit`, `revert`) enqueue into an IndexedDB FIFO `leg_mutation_queue` store (`mutation_id`, `event_id`, `leg_id`, `action_type`, `payload`, `is_explicit_revert`, `client_updated_at`, `previous_leg_snapshot`, `queued_at`, `retry_count`, `sync_state`) and reflect immediately in the UI.
- [ ] Queue flushes FIFO through `apply_leg_mutation(...)` on `online`, `visibilitychange` (`visible`), `focus`, and a 15-second exponential backoff timer while non-empty; whenever queued items exist, a tappable `44px`-tall **"Saved locally (N) — Sync now"** pill appears in the header/chrome, and queued items remain intact across expired or revoked sessions until the Participant re-unlocks the Event.
- [ ] When `apply_leg_mutation` returns `{ applied: false, reason: 'stale_or_overridden', leg }`, the client drops the stale queue entry, updates local state and `event_snapshot` to the authoritative server `leg`, and displays a brief neutral toast (*"Updated to latest Basecamp status"*).
- [ ] The ~8-second `popover="manual"` **Undo** toast is offline-aware: tapping Undo while the mutation is still pending locally deletes it from `leg_mutation_queue` and restores `previous_leg_snapshot` with zero network call; tapping Undo after flush enqueues a compensating `revert` mutation restoring `previous_leg_snapshot` with `is_explicit_revert = true`.
- [ ] All structural and Organizer-bulk actions (RSVP edits, Team create/join/leave, Supply claims and volunteered items, Event/Course/Announcement edits, `Start Round N`, chip-ins, Organizer Badges) show a clear disabled **"Requires connection"** state when offline.
- [ ] Automated tests verify offline cold-launch hydration with optimistic queue overlay, FIFO flush triggers and exponential backoff, stale-override reconciliation toast, pre-flush vs. post-flush Undo behavior, preserved queue on auth expiry, Service Worker update deferral when queue is non-empty, and disabled *"Requires connection"* UI states.
